# CertCenter 自动化与运行

首期通过常驻服务中的持久化任务队列实现自动签发、续期和上传。CertCenter 运行模式没有挂载原 ConfigCenter 的 MCP 配置操作入口。外部自动化可在 ConfigCenter 中维护域名策略，由 CertCenter 通过 SDK 读取执行。

## 任务生命周期

`queued` → `running` → `succeeded` / `failed`。

同一域名/证书策略使用数据库唯一活动键互斥。每个运行任务有 20 分钟租约，操作上下文限制为 10 分钟；进程停止后，租约过期的任务可以恢复。完成后释放活动键。签发结果按任务唯一保存；已保存的版本在恢复时继续部署。若进程在 CA 签发成功、数据库保存之前崩溃，恢复可能重新请求证书，需留意 CA 配额。

失败的自动任务一小时后重试。成功上传回执绑定证书版本、上游名称和目标配置摘要。更改目标配置后自动重新上传；手工部署也会重新执行。腾讯云使用禁止重复上传选项，阿里云使用证书指纹作为幂等 token；网络超时与服务端成功之间仍可能存在不确定结果，应结合云端证书 ID 核查。

任务和日志保存于数据库，网页展示最近 100 个任务和 500 条日志；历史证书保留。当前没有自动历史清理功能，请监控数据库容量。

## 部署方式

服务需要持续运行，建议使用 systemd、容器或其他常驻进程管理方式。反向代理提供 HTTPS，OAuth 回调使用公开地址。避免使用会在无 HTTP 请求时冻结进程的运行模式，否则后台检查无法按时执行。

例如，systemd 服务可使用以下运行设置（先创建用户并准备配置文件）：

```ini
[Service]
User=certcenter
WorkingDirectory=/opt/certcenter
EnvironmentFile=/opt/certcenter/.env.local
ExecStart=/opt/certcenter/.tmp/bin/certcenter
Restart=on-failure
```

多工作进程共享同一数据库时使用租约抢占任务。ConfigCenter 的配置写入 API 没有 CAS；管理写入应由单个实例承接。每次操作读取最新远端配置；配置获取失败不使用过期凭据继续执行。

服务启动配置变更需要重启。DNS/provider、上游、域名策略和注册开关在使用时重新读取。加密密钥不可直接轮换，数据库恢复时必须配套同一密钥。
