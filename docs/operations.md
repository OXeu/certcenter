# CertCenter 自动化与运行

首期通过常驻服务中的持久化任务队列实现自动签发、续期和上传。CertCenter 运行模式没有挂载原 ConfigCenter 的 MCP 配置操作入口。外部自动化可通过 SDK 在远端 ConfigCenter 或本地 KV 中维护域名策略，由 CertCenter 通过同一 SDK 读取执行。

## 任务生命周期

`queued` → `running` → `succeeded` / `failed`。

同一域名/证书策略使用数据库唯一活动键互斥。每个运行任务有 20 分钟租约，操作上下文限制为 10 分钟；进程停止后，租约过期的任务可以恢复。完成后释放活动键。签发结果按任务唯一保存；已保存的版本在恢复时继续部署。若进程在 CA 签发成功、数据库保存之前崩溃，恢复可能重新请求证书，需留意 CA 配额。

失败的自动任务一小时后重试。成功上传回执绑定证书版本、上游名称和目标配置摘要。更改凭据或上传目标后自动重新上传；只修改资源更新、清理开关和联系人不会丢失回执。云上游的手工部署也复用已上传的当前版本，SSH 手工部署仍重新执行。腾讯云使用禁止重复上传选项，阿里云使用证书指纹作为幂等 token；上传超时与服务端成功之间仍可能存在不确定结果，应结合云端证书 ID 核查。

云资源更新按“上传 → 查询旧绑定 → 创建/恢复更新任务 → 检查全部资源成功 → 可选清理”执行。上传 ID、旧证书 ID、资源范围和异步任务 ID 分别持久保存；每次推进后保存检查点。云任务进行中时，操作返回 `queued`，保留策略活动锁，15 秒后继续，避免阻塞其他策略或重复签发。失败重试沿用已上传的新证书和原云任务。腾讯云重试原更新任务，阿里云只重试失败的资源子任务。

清理仅针对相同域名、策略、上游和凭据配置下的旧上传。新证书必须覆盖旧证书的全部 SAN。腾讯云使用带绑定检查的异步删除，并等待删除任务成功；阿里云检查旧证书在云资源列表中已无绑定，且本次更新的全部资源已绑定新证书后删除。查询失败、结果不完整、回滚、资源更新失败或旧证书仍有绑定时不会删除。未纳入云厂商资源列表的外部安装不属于此流程；本地加密证书历史始终保留。

任务和日志保存于数据库，网页展示最近 100 个任务和 500 条日志；历史证书保留。当前没有自动历史清理功能，请监控数据库容量。

## 部署方式

服务需要持续运行，建议使用 systemd、容器或其他常驻进程管理方式。反向代理提供 HTTPS，OAuth 回调使用公开地址。避免使用会在无 HTTP 请求时冻结进程的运行模式，否则后台检查无法按时执行。

例如，systemd 服务可使用以下运行设置（先创建用户并准备配置文件）：

```ini
[Service]
User=certcenter
WorkingDirectory=/opt/certcenter
EnvironmentFile=/opt/certcenter/.env.local
ExecStart=/opt/certcenter/.tmp/bin/certcenter
Restart=on-failure
```

多工作进程共享同一数据库时使用租约抢占任务。ConfigCenter 的配置写入 API 没有 CAS；管理写入应由单个实例承接。每次操作通过 SDK 读取当前存储中的最新配置；远端获取失败不会隐式转为本地存储。

服务启动配置变更需要重启。DNS/provider、上游、域名策略和注册开关在使用时通过 SDK 重新读取。加密密钥不可直接轮换，数据库恢复时必须配套同一密钥。

## 内置验证 DNS

启用 `acme_dns` 后，同一进程额外监听 TCP 和 UDP DNS。启动时绑定端口失败会直接报错，进程退出时关闭监听。公网验证需要开放两种协议的 53 端口及正确的 NS 委派；仅转发 HTTP/HTTPS 不够。配置步骤见[内置 acme-dns 委派](/docs/config)。

CNAME 标识和短期 TXT 值都存储在关系数据库中。备份数据库可保留用户已经添加的 CNAME；切换验证区域或丢失委派表后需要用户更新 CNAME。多实例提供 DNS 时应共享同一数据库。旧挑战值到期后不再回答，并在该目标下次写入时清理。
